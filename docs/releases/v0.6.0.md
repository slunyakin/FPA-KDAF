# KDAF v0.6.0 Release Notes

Release scope: Evaluation and Public Adoption Evidence

## Capabilities

- repeatable evaluation runs for retrieval, grounding, provenance, validation completeness,
  citation validity, and unsupported-claim refusal
- durable per-case evaluation results in framework metadata with stable machine-readable failures
- a versioned seven-case public FP&A benchmark covering variance, budget versus actuals, forecast,
  department spend, revenue drivers, provenance-heavy evidence, and refusal
- an adoption-ready public demo from project creation and starter-kit loading through CARP retrieval,
  DWH evidence, a cited answer, refusal verification, and stored evaluation metadata
- aligned core, CLI, tool-server, and script entrypoints
- a public readiness report with automated test evidence, optional Docker status, architecture
  coverage, supported workflows, unsupported areas, and roadmap candidates
- fresh-clone quickstart, architecture overview, benchmark/demo tutorials, and role-based guidance

## Architecture guarantees

- Neo4j stores semantic graph context, relationships, provenance links, and validation state.
- The metadata database stores framework metadata, audit workflow, and evaluation state.
- The separate financial DWH stores numbers, measures, and fact rows.
- Financial numbers are not stored in Neo4j.
- Public surfaces invoke shared core services and use stable machine-readable error shapes.

## Limitations

- the release is ready for local evaluation and early-adopter inspection, not as a production deployment template
- extraction supports CSV only
- project/MVG/source/extraction relevance associations are not fully automatic
- local extraction and starter-DWH workflows do not yet use production Postgres persistence adapters
- the public benchmark covers a small starter FP&A domain rather than all finance workflows
- live Docker/Neo4j/Postgres status depends on the adopter environment; the published readiness run
  skipped live integration because Docker was unavailable
- identity, authorization, multi-tenancy, retention, monitoring, backup, recovery, and deployment
  hardening are outside this release
- provider-specific retry, rate-limit, streaming, and production observability are outside this
  release
- citations demonstrate linkage to supplied evidence, not source accuracy or analytical correctness

## Validation baseline

At adoption-package preparation, the full suite passed with only clean Docker-unavailable skips,
Ruff passed, the public FP&A benchmark passed 7/7 cases, and the documented offline demo passed. See
the [v0.6 readiness report](../release-readiness-v0.6.md) for exact evidence and interpretation.

## Upgrade notes

- Package and public runtime version metadata now report `0.6.0`.
- Existing v0.5 CARP, evidence-packet, and grounded-answer interfaces remain available.
- Metadata schema initialization adds evaluation-result fields idempotently for existing local
  stores.
- No migration writes financial facts to metadata or Neo4j.
